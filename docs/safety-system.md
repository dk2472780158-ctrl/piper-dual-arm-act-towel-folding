# 安全机制

安全是本项目第一优先级：控制环上每个动作在发出前都要通过完整校验，评测默认 dry-run，任何未经确认的硬件动作都会被拒绝。

## 1. 安全校验器（`src/piper_towel_folding/safety.py`）

纯 numpy、无依赖，可独立单测（`tests/test_dry_run.py`）。每个控制步按序执行：

| # | 校验 | 限制 | 触发后果 |
|---|---|---|---|
| 1 | 动作形状与有限性 | 14 维、无 NaN/Inf | 拒绝该动作 |
| 2 | 硬件限位 | Piper SDK 物理关节范围 | 安全停机 |
| 3 | 逐命令步长 | 关节 ≤ 0.10 rad，夹爪 ≤ 0.01 m | 安全停机 |
| 4 | 跟踪误差 | 关节 ≤ 0.35 rad，夹爪 ≤ 0.03 m | 安全停机（卡滞/被阻挡） |
| 5 | 起点位姿校验 | 距训练起点关节 ≤ 0.15 rad，夹爪 ≤ 0.02 m | 拒绝启动 |
| 6 | 夹爪裁剪 | [0, 0.08] m | 静默修正（Piper 对负目标取 `abs()`，显式裁剪保证确定行为） |

> 第 3 条防止「单步猛拉」，是模仿学习 rollout 最常见灾难场景。第 4 条在机械臂卡住或被人为阻挡时停止推进力矩。

## 2. 电机生命周期安全

- **永不发送 disable 指令**：连接、执行、异常退出、断开全程保持机械臂 ENABLED，防止断电后机械臂坠落伤人/损坏。
- 控制异常（安全校验失败 / 跟踪误差超限）时策略为 **hold 保持**（`--shutdown hold` 默认），而不是立即掉使能。
- 关节滤波默认关闭（`PIPER_ACTION_FILTER_ALPHA=1.0`），如需滤波显式开启并调参。

## 3. 双重确认机制

| 层级 | 机制 |
|---|---|
| 默认状态 | 所有脚本 / 评测默认 **dry-run**，不使能电机、不动作 |
| `--execute` | 必须显式传入 |
| `EXECUTE` 键入 | 执行时需人工键入 `EXECUTE` 确认 |
| `--max-steps` | 真实执行必须有正数预算；0 会被拒绝 |
| 复位 | 需 `--execute` + `MOVE` 确认 |

## 4. 操作红线（逐字保留）

发布与使用本仓库必须遵守：

1. 原始 ACT 项目只能读取，不能直接修改。
2. 必须创建一个新的、独立的 GitHub 发布目录。
3. 不允许覆盖原始训练配置、推理代码、模型或数据。
4. 不允许修改正在使用的 ACT checkpoint。
5. 不允许未经确认连接或控制机械臂。
6. 不允许未经确认执行 CAN 命令。
7. 不允许未经确认向 GitHub 推送。
8. 所有修改先保存在新的发布目录中，完成审查后再由我决定是否上传。

## 5. 上机前检查单

1. 机械臂物理固定、供电正常、急停在手边。
2. `./scripts/check_environment.sh` 通过。
3. `./scripts/dry_run.sh` 全流程通过。
4. 机械臂已用复位工具慢速归到训练起点。
5. 二次检查无人、无障碍物位于工作空间与线缆路径。
6. 执行人员持急停，另一人观察工作区与线缆管理。

## 6. 安全事件记录

`safety_events` 字段记录在 `results/evaluation_summary.json`：安全停机次数、步长违规、跟踪误差停机、起点拒绝、急停触发等，全部回填真实数据。
